# CLAUDE.md

Guidance for working in **aws-sagemaker-pp**: a scikit-learn random forest
trained in a SageMaker training job and served from Serverless Inference.
Read "Rules That Are Load-Bearing" before changing `ml/`, `sagemaker_demo/`
or the IAM policy.

## Shape

    01-infrastructure/   Terraform: bucket, notebook + execution roles, notebook instance,
                         lifecycle script (scripts/on-start.sh), project files -> S3
    02-mcp/              Terraform: remote MCP connector (Cognito, HTTP API, router Lambda);
                         code/ = router.py + oauth.py from aws-cognito-mcp, mcp.py (the tool)
    ml/                  Runs in the SageMaker container: dataset, train, inference
    sagemaker_demo/      boto3 orchestration (no SageMaker SDK), shared by notebook + CLI
    demo.py              CLI over sagemaker_demo
    notebook/            Generated by make_notebook.py -- edit the generator, not the .ipynb

Terraform owns static things. Python owns training jobs, models, endpoint
configs and the endpoint. `destroy.sh` destroys 02-mcp, then runs
`demo.py cleanup --purge-data`, then destroys 01-infrastructure.

## Rules That Are Load-Bearing

- **One image for training and serving**
  (`sagemaker-scikit-learn:1.4-2-py312-cpu-py3`). `model.joblib` is a pickle;
  the scikit-learn that loads it must be the one that wrote it.
  `ml/requirements.txt` mirrors that image's pins, and `requirements.txt`
  (the notebook kernel and the CLI) must agree on numpy, pandas,
  scikit-learn, scipy and joblib. A test enforces this. Changing the image
  version means changing all three.
- **The kernel is Python 3.10** (conda_python3 on notebook-al2023-v1). That
  caps scikit-learn at versions with cp310 wheels, and scikit-learn 1.4.2
  also caps the CLI at Python 3.12.
- **`PIP_NO_BUILD_ISOLATION=false` in the model environment.** The container
  pip-installs `/opt/ml/model/code` at start-up. With build isolation on,
  pip downloads setuptools from PyPI, so the endpoint would need internet
  access to start. `false` means *off*, because pip reads `PIP_NO_*` inverted.
  Verified offline by `tests/smoke_serving_stack.py`.
- **`PIP_BREAK_SYSTEM_PACKAGES=1` and `PYTHONPATH=/opt/ml/model/code`** in
  the model environment. Both were found by live endpoint failures. The
  image's Python is Debian's (PEP 668), so the start-up `pip install .` is
  refused without the first. The server runs as the non-root
  `model-server`, so pip installs into `~/.local`, which is not on the
  running process's `sys.path`, hence the second. The stand-in image
  reproduces both (EXTERNALLY-MANAGED marker; the smoke test serves as uid
  1000 with the model environment set before the process starts).
- **The first call to a cold serverless endpoint can get nginx's 502** (seen
  live). `invoke()` retries 502/503/504 ModelErrors, bounded.
- **SageMaker Runtime reports a missing endpoint as `ValidationError`**, not
  `ValidationException`.
- **Serving code ships inside the artifact.** `train.py` copies
  `inference.py` to `/opt/ml/model/code/`; the model's
  `SAGEMAKER_SUBMIT_DIRECTORY` is that directory. Do not point it at S3.
- **`input_fn` returns errors, never raises.** An exception becomes a bare
  500. `RequestError` flows through `predict_fn` to `output_fn`, which
  answers 400 through `sagemaker_containers`' `worker.Response` (the only
  way to set a status in that stack).
- **Hyperparameter values are strings**, and the `sagemaker_*` paths are
  JSON-encoded strings, as the SDK sends them. Every other key becomes a
  `--flag` that `train.parse_args` must accept. Tested.
- **Names start with the prefix and match `iam.tf`'s patterns**
  (`-train-`, `-model-`, `-epc-`, `-endpoint`). The notebook role is scoped
  by those patterns, and cleanup finds resources by them. A test parses
  `iam.tf` and checks every generated name against it.
- **Names are recorded in `state/resources.json` before each create call.**
  Cleanup unions that file with a name search, so either one can be lost.
- **`source_tarball()` must stay byte-reproducible**: mtime 0 on every tar
  entry *and* `GzipFile(mtime=0)`. Otherwise the content-hash key changes
  every second and each run uploads a duplicate.
- **The bucket is not `force_destroy`.** Cleanup deletes only the demo's
  prefixes (`data/`, `code/`, `training-output/`, `state/`); Terraform
  deletes `notebook-source/`. Anything else blocks the destroy on purpose.
- **`n_jobs=-1` makes `predict_proba`'s last bits vary between calls**
  (threaded summation). Compare probabilities with a tolerance, or compare
  the fitted trees. The fit itself is deterministic.
- **The lifecycle script must finish within 5 minutes**, so the kernel
  virtualenv builds in the background (`nohup`, stdin from `/dev/null`).
  It is rebuilt only when `requirements.txt`'s hash changes, and
  re-registered on every start (`~/.local` is not persistent).
- **`sagemaker_demo` must import without numpy.** `destroy.sh` runs cleanup
  with only boto3. `ml/` modules are imported lazily
  (`workflow.ml_module`).

## MCP Connector (02-mcp)

- **`oauth.py` and `router.py` are copies of aws-cognito-mcp's, unchanged.**
  That flow (RFC 8414 metadata, RFC 7591 dynamic registration, and brokering
  claude.ai's per-organisation redirect_uri) is proven against claude.ai.
  Fix bugs there and copy them over; do not fork them here.
- **Self sign-up is open** (the owner's choice): anyone with the URL can
  register and call the synthetic model. `add_mcp_user.sh` creates users
  without email; flip `allow_admin_create_user_only` to lock it down.
- **Token check: userInfo, then GetUser.** userInfo rejects tokens without
  the `openid` scope. The Hosted UI (claude.ai) issues `openid`; the admin
  sign-in that validate.sh uses issues `aws.cognito.signin.user.admin`
  (confirmed live). Removing the GetUser fallback breaks validate.sh, not
  Claude.
- **30-second budget.** API Gateway HTTP APIs give an integration 30 s, so
  the Lambda timeout is 29 s and `mcp.py` retries cold-start 502/503/504 for
  at most 24 s.
- **Tool errors are results with `isError`, not JSON-RPC errors**, so the
  model reads "reading is missing operating_hours" and can fix its call.
  Field validation stays in `inference.py`; `mcp.py` only checks the shape
  of `readings`.
- The router's only SageMaker permission is `InvokeEndpoint` on
  `<prefix>-endpoint`. That name must match `Config.endpoint_name`; a test
  checks it.

## Testing Without Deploying

`./tests/run_local_checks.sh` (Docker + Terraform, no AWS calls):

- `tests/docker/container.Dockerfile` rebuilds the scikit-learn container's
  Python and serving/training stack from its public sources at tag
  v1.4-2-py312. pytest runs there.
- `smoke_training_stack.py` writes `/opt/ml/input/config` from the real
  `CreateTrainingJob` request and runs the container's training `main()`.
  It needs `--add-host algo-1:127.0.0.1`; without it, sagemaker-training
  hangs resolving the host.
- `smoke_serving_stack.py` serves through
  `sagemaker_sklearn_container.serving.main` from a fresh process (so
  `ml/` is not importable), with `--network none`.
- `smoke_notebook_offline.py` runs the notebook's non-AWS cells in a
  Python 3.10 image built from `requirements.txt`, against the 3.12 artifact.

After editing `make_notebook.py`, run `python3 make_notebook.py`; a test
fails if the committed notebook differs.

## Code Commenting Standards

Comment the *why*, not the *what*. Explanations aimed at the demo's audience
belong in the notebook's markdown and the README, not in code comments.
